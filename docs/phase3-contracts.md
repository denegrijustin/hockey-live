## Conventions
- **Team id** = the NHL abbreviation in `src/data/teams.json` (`EDM`). **Player id** = the numeric NHL playerId (use `String(id)` in URLs, 7 digits). **Game id** = the numeric NHL game id (`2026020001`). **Season** = 8-digit (`20262027`) from `useSeason`; label "2026–27". Never invent identifiers.
- **Stats**: a missing value is `—` (never 0, never NaN); every number that is a window carries its timeframe label ("Last 10 games", "Season to date", "Reported <date>"); a derived value (rate, rank gap, insight) is marked "Derived" and its definition lives in the pure helper's doc comment AND a node test. Nothing predictive is stated as fact.
- **States**: loading = existing `Skeleton` (fixed height) or `<p role="status">`; empty = one sentence naming what is missing; error = one sentence + Retry where a retry exists. Page headers use `PageHeader` (src/components/PageHeader.tsx); identities use `TeamLogo`/headshots with `alt=""` when a name sits beside them.
- **Cross-links**: team -> `TeamLink`/`useTeamProfile()`; player -> `usePlayerProfile()` (`src/components/player/PlayerContext.tsx`, stub now, Agent 2 implements); game -> `openGame(id)` (`src/lib/open-game.ts`, Agent 6 wires the listener on Home); view -> `onNavigate(view)`/`setView`. No dead ends: every profile has a way to its team, its games, standings and injuries where supported.
- **Existing selectors that tests rely on stay** (see the QA audit): `dialog.team-dialog` named "<name> profile" with h2 name, headings "Recent results" and "Injuries", exactly 3 `.tp-ranks span`, close label "Close team profile"; player button name "View <name> details", `dialog.player-dialog`, close "Close player details", `/api/player/:id` keys; standings labels "Group standings", "Standings view", "Standings table", "Resumés", "Projected PTS", 32 `tbody tr`; `input[aria-label="Find a matchup"]`; `getByTestId("injury")`.
- **URL**: `searchFor(view,date,extra)` in `src/lib/date-nav.mjs` is the one place query strings are built (lead extends it: `team` is kept only on `view=teams`, `player` is kept on any view while a player dialog is open). Agents do not hand-write query strings.
