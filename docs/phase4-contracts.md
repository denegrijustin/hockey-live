# Phase 4 contracts (lead-owned; agents build to these)

## Principles
Anonymous and local-first. No accounts exist (the Worker is a stateless GET-only proxy), so everything is **device-local**; the UI must say so ("Saved on this device"). Personalization prioritises, it never hides: every view keeps a one-tap path to the whole league. No fabricated data or reasons. All new views/dialogs are **lazy chunks**: the main JS chunk has ~2 KB headroom (budget 135 KB/file, CSS 32 KB/file), so do not grow `index-*.js` beyond what is in this doc.

## Identifiers
Team = NHL abbreviation (`teams.json`); player = 7-digit NHL id (never name, never ESPN id); game = numeric NHL game id (stable across reschedules; never key by date).

## Preference store (DONE, lead): `src/lib/prefs.mjs` (pure, tested) + `src/lib/prefs.ts` (store)
Key `iceboard-prefs-v1`, schema in `defaultPrefs()`: `favorites[]`, `onboarded`, `players[{id,name,team,pos,number,headshot,at}]`, `games[{id,season,home,away,date,at}]`, `display{theme,contrast,motion,textSize,timeZone,hour12,density,defaultView,homeOrder,sections{myTeams,myPlayers,worth,pulse}}`, `alerts{enabled,start,period,final,schedule,scope{teams,players,saved}}`. Caps: 32 teams, 100 players, 100 games. Legacy `iceboard-teams` is migrated into `favorites` (and marks `onboarded`). Corrupt/unknown values sanitise to defaults; storage failures keep an in-memory copy (`prefsPersisted()` false => show a notice). Other tabs sync via the `storage` event.
API: `usePrefs()`, `getPrefs()`, `setPrefs(next | fn)`, `resetPrefs()` (only Iceboard's keys), pure reducers `toggleFavorite/toggleFollow/toggleSaved`, `isFavorite/isFollowing/isSaved`. **Nobody writes localStorage directly**; add fields only via Agent 6 (schema owner) with a migration + test.
Behaviour decision: **no favorites => league-wide experience** (Games/Home show all 32 teams; no hardcoded EDM/CHI/MIN for new visitors). With favorites, the Games filter defaults to them but "All teams" is one tap.

## Notification (alert) model — Agent 4
`src/lib/alerts.mjs` (pure): `diffGames(prevMap, games, now) -> events[]`; event `{id, kind: start|period|final|schedule, gameId, teams[], title, body, at}`. Event ids are deterministic (`${gameId}:start`, `${gameId}:p${period}${periodType}:end`, `${gameId}:final`, `${gameId}:${PPD|CNCL|SUSP}`) so duplicates are impossible; `seen` ids persist in `iceboard-alerts-v1` (capped 300, TTL 3 days, separate from prefs). First snapshot is a silent baseline; stale-live games (`isFreshLive`) never alert; score decreases never alert. Scope: favorite teams, followed players' teams only when the game is relevant ("plays tonight" is an availability fact, not an injury claim), saved games. Delivery Stage A in-app (bell in header + notification center sheet + toasts, unread count). Local `Notification` only after an explicit button and only while the page is open. **Web Push is NOT built** (needs VAPID secrets, a subscription store and POST routes the Worker does not have); the UI must not claim background delivery.

## Relevance score — Agent 5
`src/lib/relevance.mjs`: `relevance(game, ctx) -> {score 0-100, reasons:[{key,points,text}]}`; ties broken by start then id. Components (each emits a reason only when its fact is true): favorite team plays +35 (+10 for a second), existing `watchability` x0.30, same division as a favorite (no favorite playing) +10, playoff-line gap within `T.lineGap` +10, top `matchupInsights` (scaled, max +10), live heat (closeAndLate/upsetBrewing, max +10), puck drop within 24h +5, saved game +20, followed player's team +10. Explanation = top 2-3 reasons joined by " · "; no reason fires => no explanation. Postponed/cancelled games are labelled, never ranked up.

## Home dedupe rule (Agent 3)
A game appears once per section family: "My Teams" carries favorite-team games for the selected day; those ids are removed from Live/Upcoming/Completed and from Worth watching, with counts computed after removal. Live favorite games sit at the top of My Teams. With no favorites the section is absent and Home is unchanged. Phones: My Teams is a single compact strip (cap 3 cards + "See all"), League Pulse collapses to one row; do not add more than ~1 screen of height on a 390x844 viewport.
