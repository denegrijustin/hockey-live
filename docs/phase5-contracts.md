# Phase 5 contracts (lead-owned; agents build to these)

## Principles
Real data only. Never show stale data as confirmed live. No new backend or transport (the NHL feed sits behind a 15 s edge cache, so polling faster than 15 s gains nothing). Fixtures for tests are recorded or *derived from real recorded data and labelled as derived*; no invented live data in the app. All new Game Center UI is lazy (main JS has ~9 KB gz headroom; the Game Center chunk is lazy already). New CSS goes in small new files (`styles.css` is already huge). Every derived metric states its definition, inputs and limits in its file header and in `docs/phase5-<topic>.md`, and is labelled Official / Derived / Projection in the UI.

## Identifiers
Game = numeric NHL id (10 digits). Event = NHL `eventId` (unique within a game; **not** chronological: order by `order`=`sortOrder`). Player = 7-digit NHL id. Team = NHL abbreviation. DOM key / store key for an event: `${gameId}:${eventId}`.

## Data already available (DONE, lead): `normalizeGameFeed` is extended additively
Every play keeps its old fields (`id, period, periodType, time, type, order, penalty, duration, team, x, y, player`) and now also: `pid` (primary player id), `left` (time remaining "mm:ss"), `sit` (NHL situationCode "ABCD" = away goalie, away skaters, home skaters, home goalie; read digit by digit: "1551" = both goalies in, 5 skaters each; "1541" = away 5 skaters v home 4 skaters; document your decoding of other values and test it), `zone`, `shotType`, `reason`, `secondary` and `other` (`{id,name}` for the other players in hits, blocks, faceoffs, takeaways...). Goals add `assists[{id,name}]`, `goalie`, `score{home,away}` (score after the goal). The feed adds `roster[{id,name,team,number,pos,headshot}]`, `clockRunning`, `clockSeconds`, `otInUse`, `shootoutInUse`. Real goal plays are not in the repo fixture (zero goals): goal shape is per the NHL API and must be verified by Agent 2 against a live/recorded completed game with `curl` (the NHL API is reachable) before relying on it.

## Shared provider (DONE baseline, lead): `src/components/gc/GameCenterContext.tsx`
`<GameCenterProvider game>` wraps the Game Center; every pane reads `useGameCenter()` -> `{game, feed, plays, status, live, stale, error, updatedAt}`. One subscription for the whole Game Center. **Agent 2 upgrades its internals only** (adaptive polling, ordering guard, reconciliation, stale flag) and may add fields (never remove or rename). Panes must not call `useFeed("/api/game/...")` themselves.

## Normalized game state (Agent 2): `src/lib/game-state.mjs` (pure, tested)
`phaseOf(gameOrFeed, {now}) -> {phase, label, live, final, clock:{period, periodType, remaining, running, intermission}, stale, reason}` where `phase` is one of `scheduled | pregame | live | intermission | overtime | shootout | final | final-ot | final-so | postponed | suspended | cancelled`. One function replaces the scattered `isLive/isFreshLive/isCalledOff/gameStatus` derivations (keep those exports working, implemented on top of it). `pregame` = PRE state; **"delayed" is not derivable from the feed: do not invent it** (document the limit; show a delay only if a real field exists). Stale-live uses the shared constant (remove the duplicated literal in worker.js). Transition detection: `transition(prev, next) -> {from, to} | null`.

## Event store and reconciliation (Agent 2): `src/lib/event-store.mjs`
`reconcile(prevStore, plays) -> {store, events, added[], changed[], removed[], voided[]}`. Keyed by eventId. Sorted by `order`. Overlapping polls never duplicate. A content hash per event detects `changed` (assists, scorer, strength). A goal that vanishes is only `voided` after **two consecutive polls** without it (debounce) and the score is lowered consistently; if a goal reappears under a new eventId with the same fingerprint (`period:time:team:pid`) treat it as the same goal, `changed`. Out-of-order responses: each request carries a sequence number; a response older than one already applied is dropped; a response whose play list is a strict prefix of the current store never shrinks it unless the removal rule above applies. Missing `time`/`order` events sort last within their period and never crash.

## Refresh strategy (Agent 2; worker + client)
Client: live running clock 15 s, intermission 30 s, pregame within 30 min of puck drop 30 s else 60 s, final: one fetch then one recheck about 3 min later (corrections) then stop, hidden tab: stop and catch up once on show, errors: exponential backoff with jitter (cap 60 s), keep the last data and mark it stale after 2x the expected interval (min 45 s). Multi-tab: one leader polls and broadcasts through `BroadcastChannel` (fallback: independent polling). Worker: `/api/game/:id` TTL 15 s live, **120 s for FINAL, 3600 s only for OFF**, unpublished game -> 404 (not 502). Keep `/api/game` response shape additive. Remove the `?score=` cache-key trick (it splits subscriptions); use one URL per game.

## Momentum spec (Agent 5)
Documented derived metric "shot-attempt pressure": team-relative, rolling window (start: 5 min, 10 s step, linear decay), weights per attempt (goal counts once, SOG, missed, blocked credited to the shooting team, optional distance-based danger multiplier from the existing `isHighDanger`), hits excluded, penalties shown as markers/power-play bands (strength from `sit`), shootout excluded, overtime windows handled, normalization documented, incremental recompute (append-only; no full history rescan per poll), text alternative + `aria-label` with the current leader and numbers, period boundaries, goal markers, inspect-by-keyboard. Label "Iceboard metric: shot-attempt pressure, not possession or win probability". Final games may use MoneyPuck xG via existing `chanceFlow` only as a clearly labelled alternative source.

## Notification contracts (Agent 7)
Goal alert id `${gameId}:goal:${eventId}` (kind `goal`, with `eventId`, team, scorer, period, time, score). Fetch play-by-play for goals only for live games that are saved or involve a favorite team, only when the scoreboard total changed or the period changed, max 6 concurrent, sharing the Game Center feed cache so an open Game Center does not double-fetch; fallback to a generic score-delta line without a scorer if the fetch fails. Overturned goal: when the event store emits `voided`, add `${id}:void` retracting the original (`retracted:true`, title "Goal disallowed"); never alert from stale data. Item store whitelist (`alerts.mjs parseState`) must carry the new fields. No push prompts.
